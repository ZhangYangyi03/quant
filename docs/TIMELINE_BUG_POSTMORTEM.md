# 时间轴错配事故复盘（2026-11-04，M154 期间发现）

## 症状

`ic_fast.json` 里 17 个因子的单因子 IC 普遍比直接复算大一倍左右：

    amt20   ic_fast = -0.2658   直接复算 = -0.1058
    size    ic_fast = -0.1267   直接复算 = -0.0673
    max20   ic_fast =  0.2188   直接复算 =  0.0667
    amt_cv  ic_fast =  0.0227   直接复算 = -0.0489（连方向都反了）

`git show 51069f3:ic_fast.json` 里 amt20 还是 -0.1164，说明是后来一次改动引入的。

## 根因：fmerge.py 第二次重建时间轴

commit 9d437f3（扩到 17 因子）在 `fmerge.py` 里先正确地按 `(交易日, 段号, 段内行号)`
排好 `JJ / SEG_OF / OFF_IN_SEG`，随后又第二次重建 `pairs`：

    pairs.extend([(int(JJ[m]), sid, m) for m in range(n)])

`JJ[m]` 是**已排序的全局日期**，而 `(sid, m)` 是**某个段自己的行号**。两者错配后，
时间轴变成 `5377, 5397, ..., 5514, 5377, 5397, ...`，183 行里混进重复月份，而且
因子行与收益行来自不同月份。按这条错轴复算 amt20 IC = -0.2631，正好复现
`ic_fast.json` 的 -0.2658；正确时间轴是 -0.1058。

## 第二处：fscan_parts 本身有重复落盘的段

24 个段里，段 26 与段 29 是同一批 8 个月（5696..5838），段 24 与段 34 有 5 个月重叠。
`fraw.meta()` 因此给出 183 行、只有 166 个唯一交易日。相邻重复月会让"当月收盘 ->
下月收盘"的远期收益恒为 0，把 IC 和组合超额一起稀释。

`fraw.meta_unique()` 现在统一按交易日去重，`fmerge.py / mlfit2.py / risk_portfolio.py`
共用这一条轴。`fraw.row / rows / matrix` 已改为**必须显式传 `_M`**，防止再把原始轴和
去重轴的下标混用（这正是 9d437f3 那类事故的成因）。

## 修复后的口径

    时间轴          166 个唯一月（原始 183 行、重复落盘 17 行），2012-08-31 ~ 2026-10-30
    可回测区间      165 个（最后一月没有下月收益），训练 76 / 测试 89
    amt20 IC        -0.1175 (t -10.33, n=165)，直接复算 -0.1181
    训练 / 测试      76 / 89 月，2019-01-01 切分
    size+amt20      测试段 1.27%/月 t4.66 换手 14.6%（mlfit2）
    A 锚点复刻      测试段 1.27%/月 t4.65（risk_portfolio）

之前 `mlfit2.py` 只把 `meta()` 换成 `meta_unique()`、没把 `_M` 传进 `fraw.rows()` 时，
曾跑出 `size 单因子测试段 16.72%/月、胜率 1.00` 的假象；那是因子行与收益行错位，
不是 alpha。传对 `_M` 之后该值回落到 1.19%/月 t4.38。

## 风险约束组合的结论（去重口径，risk_portfolio.py）

所有配置都在同一条 166 月时间轴 / 165 个回测区间上，基准 = 当期可交易池等权收益，FEE=0.001，持仓 50 只。

   升到 0.0352，说明这两个不是 size/amt20 的变体。

## 结论

- 旧 `ic_fast.json / fbeta.json` 里 17 因子的 IC 与两段检验在 9d437f3 之后是错的，
  已由 `fmerge.py` 重跑覆盖；`mlfit.json` 里 `size+amt20` 的 1.27%/月 t4.66 这个
  结论在去重口径下仍然成立，因为测试段本来就没有重复月。
- 以后凡是新增面板扫描，先跑 `tests/test_regressions.py` 里的时间轴断言，
  再跑 `fmerge.py` 覆盖结果文件。
